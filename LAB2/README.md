# Lab 2 – Agile Backlog Creation & Sprint Simulation in Jira

**Problem Statement #43:** Feature Flag & Dynamic Config Manager  
**Author:** Akshat Shaurya  
**SRN:** PES2UG24CS047  

## Overview
This lab applies the Agile workflow in Jira to a Feature Flag & Dynamic Config Manager: a system that lets teams turn features on or off, target users, set per-environment values and sync changes to client apps in real time, without redeploying.

The work covers building a product backlog of Epics and user stories, estimating story points, planning and running two sprints, and reviewing the results through burndown charts and reflection questions.

## What the report covers
- **Jira Backlog:** 6 Epics and 12 user stories, each written as "As a … I want … so that …"
- **Story Point Assignments:** estimates for every work item
- **Sprint Boards:** To Do, In Progress and Done for Sprint 1 and Sprint 2
- **Burndown Charts:** one for each sprint
- **Reflection Questions:** estimation accuracy, prioritization, plan vs. actual, team capacity
- **Final Work Item Verification:** the full list of Jira work items with types and priorities

## Epics

| Epic | Focus |
| :--- | :--- |
| Feature Flag Evaluation & Targeting | Serving the right variation to each user; cohorts and gradual rollouts |
| Feature Flag Lifecycle Management | Create, update, enable/disable, archive and roll back flags |
| Environment-Specific Configuration | Separate values for dev, staging and production |
| Client SDK Synchronization | Real-time flag updates to client applications |
| Audit Logging & Authentication | Secure login and a traceable change history |
| Performance & Reliability | Low-latency evaluation, uptime and restricted production access |
